## Test Cases

### MP-22: Batch Management

#### TC-01: Access control — admin only
- **AC:** MP-22 #1, #2
- **Priority:** Critical
- **Precondition:** Logged in as registrar
- **Steps:**
  1. Navigate to `/admin/batches` via URL bar
  2. Call `GET /admin/batch` via API with registrar JWT
- **Expected:** Frontend redirects to `/403`; API returns 403

#### TC-02: Batch list table with all columns
- **AC:** MP-22 #3
- **Priority:** High
- **Precondition:** Logged in as admin; batches exist
- **Steps:**
  1. Navigate to `/admin/batches`
  2. Inspect table columns
- **Expected:** Columns: batch name, program, trainer, capacity, start/end date, status, actions

#### TC-03: Empty state when no batches
- **AC:** MP-22 #4
- **Priority:** Medium
- **Precondition:** No batches in database
- **Steps:**
  1. Navigate to `/admin/batches`
- **Expected:** Empty state component rendered (no blank white box)

#### TC-04: Create batch with all fields
- **AC:** MP-22 #5, #6, #13
- **Priority:** Critical
- **Precondition:** Programs and trainers exist
- **Steps:**
  1. Click "Create Batch"
  2. Verify program and trainer dropdowns pull live API data
  3. Fill all fields (program, trainer, capacity, start/end dates, remarks)
  4. Click Save
- **Expected:** Batch created; toast shown; appears in table

#### TC-05: Auto-generated batch name
- **AC:** MP-22 #7, #13
- **Priority:** High
- **Precondition:** None
- **Steps:**
  1. Create a batch with batch_name left blank
- **Expected:** DB trigger auto-generates batch name; generated name appears after save

#### TC-06: Status chips with distinct colors
- **AC:** MP-22 #8
- **Priority:** Medium
- **Precondition:** Batches in OPEN, ONGOING, CLOSED, CANCELLED statuses
- **Steps:**
  1. View the batch table
- **Expected:** Each status has a distinct color chip

#### TC-07: Edit batch pre-fills all fields
- **AC:** MP-22 #9
- **Priority:** High
- **Precondition:** Batch exists
- **Steps:**

  2. Inspect modal fields
- **Expected:** All existing values pre-populated

#### TC-08: Status change with confirmation dialog
- **AC:** MP-22 #10
- **Priority:** High
- **Precondition:** Batch in OPEN status
- **Steps:**
  1. Change status dropdown to ONGOING
  2. Observe confirmation dialog
  3. Confirm
- **Expected:** Confirmation dialog shown before save; status updated after confirm

#### TC-09: Form validation before API call
- **AC:** MP-22 #12, #18
- **Priority:** High
- **Precondition:** On create/edit form
- **Steps:**
  1. Leave required fields blank, click Save
  2. Set end date before start date, click Save
- **Expected:** Step 1: required field errors; step 2: "End date must be after start date" error

#### TC-10: Invalid trainer or program returns error
- **AC:** MP-22 #19, #20
- **Priority:** Medium
- **Precondition:** None
- **Steps:**
  1. Call `POST /admin/batch` with non-existent trainer ID
  2. Call `POST /admin/batch` with archived program ID
- **Expected:** Step 1: 404; step 2: 400 with clear message
